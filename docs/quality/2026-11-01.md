# Quality check 2026-11-01

The ten engineering rules, checked against the M1 code (written 2026-11-14, updated 2026-11-15 for the owner-secret fix and Go 1.26.11; file name
kept the same as the other repositories).

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | pass | Every store call has a timeout: `lock` wraps each in `OpTimeout` (5 s) and caps keep-alive calls at the lease deadline (`lock.go` `keepAlive`); `etcdkv` sets a per-request timeout (3 s), retries only transport errors and 5xx, at most 3 times with doubling backoff, stops when the caller's context ends (`TestGivesUpAfterAttempts`, `TestRequestTimeout`, `TestCallerCancelStopsRetries`, `TestClientErrorsAreNotRetried`). `Acquire` retries only `ErrUnavailable`, with capped jittered backoff, bounded by its context. Errors are returned or joined (`errors.Join` with cleanup errors). Ignored errors, each commented: JSON encode after headers are sent (`api.writeJSON`), response body close and the best-effort read of an error body (`etcdkv.once`), release of a lock taken in violation inside the demo. The HTTP server has read-header, read, write and idle timeouts and a 10 s shutdown. |
| 2 | Writes safe to retry | pass | Create is a compare-and-create; a retry after a lost reply finds the key on its own lease and keeps the lock (`TestRetryAfterALostCreateAnswerKeepsTheLock`). Release deletes only if the lease matches and treats "lease not found" on revoke as done; calling it twice is tested (`TestReleaseIsIdempotentAndNeverDeletesAnotherHolder`, API `DELETE` with the secret twice gives 204; `Client.Release` by name twice is tested). A retried grant can leave an unused lease that expires after its TTL (ADR 0003). |
| 3 | No race conditions | pass | memkv state is behind one mutex; `Lock` fields changed after start (`until`, `err`) are behind its mutex, `end` and stop use `sync.Once`. Two defects found and fixed while building, plus a data race in the API test's fake clock (results doc). Keep-alive and release by name read, check the secret, then act on the stored lease; the act compares that lease (`DeleteIfLease`, lease-scoped keep-alive), so an expiry in between cannot affect a new holder (ADR 0004, `TestStaleHolderCannotTouchTheNewHolder`). Concurrent tests: `TestConcurrentCreateHasOneWinner` (64 goroutines), `TestConcurrentAcquireIsMutuallyExclusive` (8x10), demo (8x25). `go test -race` runs in CI (no cgo locally). |
| 4 | Don't trust the clock | pass | Lease deadlines use `time.Now()` readings compared with `Before`/`Add`, which use Go's monotonic clock; memkv takes an injected clock. The client deadline is counted from the send time of the last keep-alive, so it is never later than the store's. Tokens come from store revision order, not time (ADR 0002). Logs are UTC (`utcTime` in `main.go`). |
| 5 | Read before changing | pass | No environment variable is read by the service (flags only: `serve -addr -etcd`, `demo -clients -rounds -ttl`). The integration test reads `DLS_ETCD_ENDPOINTS`, documented in the README, Makefile and CONTRIBUTING. The gateway paths and JSON fields follow etcd's v3 gateway documentation; that they match the real server is verified only in CI (not yet run), stated in README and results. |
| 6 | Never break compatibility | pass | First version of the API. Lease ids are JSON strings (64-bit ids are unsafe as JSON numbers in JavaScript). Unknown request fields are rejected, so a future field cannot be silently ignored by an old server. |
| 7 | One source of truth | pass | The store is the only copy of lock state; the HTTP service holds none, and the client's `until` is a conservative local view of the store's deadline, documented as such. Go 1.26.11 appears in CI (both jobs), README, CONTRIBUTING, Makefile and `.tmp/check.sh`; `go.mod` says `go 1.26.0` (minimum language version); etcd v3.6.4 only in the workflow. |
| 8 | No secrets, validate input | fixed | Secret grep finds nothing. Security review (HIGH): the lease id was the only proof of ownership for keep-alive and release, and lease ids are sequential in memkv and visible in `GET`/409. Fixed (ADR 0004): 256-bit owner secret from `crypto/rand`, stored as SHA-256, compared with `subtle.ConstantTimeCompare`, required in the library and the API (`Lock-Secret`, 401/403), never logged (`TestSecretsDifferPerAcquisitionAndAreNotLogged` reads the server log), `Cache-Control: no-store` on answers. Inputs validated with clear errors: lock names and owners (character set, length 1..128), TTL (100 ms..10 min), owner secrets (required; over 128 characters refused before hashing), stored lock values (must be this service's JSON, else an error), JSON bodies (4 KiB, `application/json`, no unknown fields, no trailing data), etcd endpoints (http(s)://host:port only, no credentials, at most 16), demo flags (ranges), store keys and values (256 B, 1 KiB), store answers (1 MiB read limit, int64 and base64 decoding errors returned). Internal errors are not leaked to HTTP clients (`TestStoreUnavailableIs503`). |
| 9 | Tests that can fail | fixed | No skips, no tautologies. Hand mutants: 13 of 15 killed before; 2 survivors killed by new tests; 9 owner-secret mutants that restore the old behaviour, all killed (table). |
| 10 | Re-verify | pass | `bash .tmp/check.sh`: gofmt and vet clean, with Go 1.26.11: `tests passed: 48 (subtests: 20)`, demo `verify:` all 0, `vulncheck: no findings` (allowlist removed), `distributed-lock-service: OK`, `CHECK PASS`. CI not yet run. |
