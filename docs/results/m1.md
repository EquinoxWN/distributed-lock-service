## Measure: the demo (`make bench`)

In-process store, 8 clients, 25 rounds each, TTL 300 ms (recorded run on Go 1.26.11,
`docs/proof/demo.jpg`):

## Analyze

- Takeover after a crash took 301 ms with a 300 ms TTL. The successor can only win after the store
  expires the lease, which is one TTL after the last renewal (at most TTL/3 before the crash), plus
  the waiter's polling delay (capped at 20 ms in the demo).
- The holder noticed loss after 303 ms: its deadline is counted from the *sending* time of its last
  successful keep-alive, so it ends no later than the store's lease does.
- Defects found while building M1:
  - **`Valid()` was briefly false right after acquisition.** The first version set the deadline
    inside the renewal goroutine. Fix: the deadline is set before the goroutine starts.
  - **Concurrent `Release` calls could close the stop channel twice.** Fix: `sync.Once`.
  - Two hand mutants survived the first test set (see the quality doc): a store that does not raise
    the revision on create (hidden because deletes raised it), and `Valid()` ignoring the deadline
    (hidden because the renewal goroutine ends the lock at the deadline). Both now have tests.
  - **Predictable ownership proof (security review, HIGH).** The first HTTP API took the lease id as
    the only proof for keep-alive (`POST /v1/leases/{id}/keepalive`) and release
    (`DELETE /v1/locks/{name}?lease_id=`). The in-process store numbers leases 1, 2, 3..., `GET` and
    409 answers show the holder's lease id, and etcd lease ids are not secrets either, so any caller
    could release or renew another holder's lock. Root cause: an identifier was used as a credential.
    Fix (ADR 0004): a 256-bit owner secret per acquisition from `crypto/rand`, stored as SHA-256,
    compared in constant time, required by `Client.KeepAlive`/`Client.Release` and the API's
    `Lock-Secret` header, never logged; the lease-id routes are removed (now 404, tested).
  - The API test's fake clock was read by server goroutines without a lock (a data race `-race`
    would report in CI). Fix: the fake clock has a mutex.

## Improve

- Deadline set at construction and `sync.Once` around the stop channel (above).
- New tests: `EveryCreateGetsANewRevision` (contract) and
  `TestValidIsFalsePastTheDeadlineBeforeRenewalsGiveUp`; both kill the mutants that survived.
- Owner secret: 7 new tests (5 in `secret_test.go`, 2 in the API tests) plus new cases in existing
  API tests and one CI-only etcd test; 9 hand mutants that bring back the old behaviour (accept any
  secret, compare always true, no missing-secret check, same secret every time, store the secret
  instead of its hash, ignore a failed check on release, the lease-id route back, the secret in `GET`,
  no revoke of a losing grant's lease) are all killed. Rejected requests before and after: a guessed
  lease id released the lock (204) before; now 403 and the holder is unchanged.

## Control

- CI `build` job: gofmt, `go vet` (also with the `etcd` tag), `go test -race`, `scripts/vulncheck.sh`,
  and the demo, whose `verify:` line is printed as a `::notice` (`::error` and a failed job on any
  violation).
- CI `etcd` job: downloads etcd v3.6.4, checks it against the release's SHA256SUMS, starts three
  members on localhost and runs `make test-etcd`; the result is printed as a `::notice`.
- Any new store must pass the shared contract in `internal/kv/kvtest`.
- Renew and release by name cannot be called without a secret: the only exported entry points take
  it, and the API has no route that takes a lease id.
